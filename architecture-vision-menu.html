01 Architecture Overview

VISION MENU follows a monorepo, full-stack architecture with clear separation between components:

📱

Public-facing, mobile-first (SSR)
📈
Restaurant Dashboard
Authenticated SPA for owners
🛠
Admin Panel
Internal platform management
⚙
Backend API
tRPC serving all frontends
⚡
Real-Time Layer
WebSocket for live notifications
💬
Background Services
WhatsApp, 3D model queue

Architecture Style: Modular monolith — start simple, extract microservices only when needed.

Example: Menu Router

TypeScript lib/trpc/routers/menu.ts
export const menuRouter = router({
  getBySlug: publicProcedure
    .input(z.object({ slug: z.string() }))
    .query(async ({ input }) => {
      return prisma.restaurant.findUnique({
        where: { slug: input.slug },
        include: { categories: { include: { items: true } }, settings: true },
      });
    }),

  toggleStock: protectedProcedure
    .input(z.object({ itemId: z.string(), inStock: z.boolean() }))
    .mutation(async ({ input }) => {
      return prisma.menuItem.update({
        where: { id: input.itemId },
        data: { inStock: input.inStock },
      });
    }),
});

12 Authentication & Authorization

Auth Strategy

  • Auth.js v5 with Credentials provider (email + password)
  • JWT strategy — stateless, no session database
  • Refresh token rotation for security

Authorization Layers

Access Control
Public Routes (no auth):
  /menu/{slug}     → Anyone can view
  /api/order       → Anyone can place order (Pro restaurants)

Protected Routes (auth required):
  /dashboard/*     → Restaurant owner only
  Access Control:  Owner can only access their own data
                   Plan-based feature gating

Admin Routes (admin role):
  /admin/*         → Platform administrators only

Plan-Based Feature Gating

TypeScript Middleware
function requirePlan(minimumPlan: Plan) {
  return async (ctx: Context) => {
    const restaurant = await getRestaurant(ctx.session.userId);
    const planHierarchy = { FREE: 0, BASIC: 1, PRO: 2 };

    if (planHierarchy[restaurant.plan] < planHierarchy[minimumPlan]) {
      throw new TRPCError({
        code: 'FORBIDDEN',
        message: `Requires ${minimumPlan} plan. Please upgrade.`,
      });
    }
  };
}

// Usage: order.create → requirePlan('PRO')

13 Multi-Tenancy Architecture

Strategy: Shared database, tenant-scoped queries. All restaurants share the same PostgreSQL database with restaurantId filtering on every query.

TypeScript Prisma Middleware
prisma.$use(async (params, next) => {
  if (params.model && tenantScopedModels.includes(params.model)) {
    if (['findMany', 'findFirst', 'count'].includes(params.action)) {
      params.args.where = {
        ...params.args.where,
        restaurantId: ctx.restaurantId,
      };
    }
  }
  return next(params);
});

Edge layer — Cloudflare

Cloudflare sits in front of the origin for four concerns in one integration: geo detection, edge caching, rate limiting, and DDoS / WAF. Free tier is sufficient for early scale.

Request flow
Client
  ↓
Cloudflare edge (cache, rate-limit, WAF)
  ↓
Origin (Django)

Cache rules

  • GET /api/public/plans/** — 1 hour TTL, vary by country
  • GET /api/public/menu/** — 5 min TTL, vary by slug
  • GET /admin/**, GET /api/dashboard/**, all non-GET — never cached

Admin writes trigger a Cloudflare cache-purge via API on post_save for billing.PlanPrice and menu models.

Rate-limit rules (edge, pre-origin)

  • 5 req/IP/min on anon auth endpoints (signup, password reset, OTP)
  • 120 req/IP/min on public menu GETs
  • 120 req/user/min on authenticated dashboard APIs
  • Admin (staff): unlimited

Django fallback via django-ratelimit for dev and non-CF paths.
